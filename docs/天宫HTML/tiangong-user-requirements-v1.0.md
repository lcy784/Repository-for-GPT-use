## 1. 项目定义

制作一个首先面向 Windows 电脑、可离线使用的三维探索与观景作品。世界包含扩大的江南水乡地面和云海中的多宫殿天宫建筑群。玩家操控一个古装人物，在地面行走、自由飞行、进入宫殿、降落屋顶，并能切换第一和第三人称。

建筑的宏大尺度与中式意境是作品的主要价值。画面尽量接近用户提供的全部参考图片，重点表现巨大宫门、长阶、柱廊、层叠宫殿、白石雕刻、云海、瀑布及可信的光影与材质。

作品以观景为主，包含必要的角色动作与轻量互动。未来扩展为支持 3—5 人一起行走、飞行和观景的联机版本；现阶段没有战斗、交易、任务或成长系统的已确认需求。

### 6.3 画面标准

- 以宏大中式幻想建筑为中心，尽量接近参考图。
- 优先保证整体尺度、建筑轮廓、空间纵深和主要光照关系。
- 强调人物与建筑的尺度差、连续柱廊、长阶、门洞、平台及宫殿群层次。
- 石材、木材、金属装饰、水面和云雾需要有可信的视觉差异。
- 宏大感应同时在人物站立视角、飞行远眺和建筑近景中成立。
- 用户允许人物采用临时模型，不要求人物与建筑达到同等写实程度。
- 不要求现实中能够建成，但“幻想世界、材质和光照可信”作为审美解释，仍需用户最终确认。
- 具体相似度、近景细节、可接受简化项和审核机位尚未量化。

| MOVE-04 | 重力与坠落 | 存在重力及坠落，不是始终悬空的自由镜头 |
| MOVE-05 | 水中活动 | 人物能够在水中活动，具体含义待确认 |
| VIEW-01 | 第一人称 | 可从人物所在位置观察与移动 |
| VIEW-02 | 第三人称 | 可看到人物及其与周围建筑的尺度关系 |
| VIEW-03 | 视角切换 | 可在第一和第三人称之间切换，继续当前探索 |

待明确的运动规则：

- 步行、奔跑、跳跃是否分别提供，以及对应速度。
- 飞行的升降、悬停、转向、加速和停止方式。
- 开启飞行后如何暂停重力、退出飞行后何时恢复重力。
- 坠落过程中是否可重新飞行，以及是否有伤害、死亡或恢复机制。
- 水中活动是水面游泳、水下潜游、浅水涉行，还是其中组合。
- 水下是否需要呼吸限制、专门视觉或专门动作。
- 第三人称镜头距离、旋转规则、遮挡处理，以及第一人称是否显示身体。
- 人物性别、服装款式及最终外观。

以上规则尚未确定；不应默认加入生命值、耐力、飞行能量或死亡惩罚。

- 不将江南参考 HTML 已有环境声自动列为新项目首版必需功能。
- 如正式加入音乐，离线版本应随附运行所需音频，不应依赖在线播放。

## 13. 性能与质量要求

| 编号 | 要求 | 当前可验收程度 |
| --- | --- | --- |
| NFR-01 | 以用户 Windows 电脑为主要目标设备 | 平台已确认；硬件细节待复核 |
| NFR-02 | 目标 60 FPS | 目标已确认；测试条件未确定 |
| NFR-03 | 宏大建筑与逼真画面优先于扩大范围 | 取舍顺序已确认 |
| NFR-04 | 可从多个角度探索，而非仅在固定机位成立 | 来自自由行走、飞行与视角切换需求 |
| NFR-05 | 离线版本在完整文件准备后可断网运行 | 可执行验收，启动方式待定 |
| NFR-06 | 交付尽量从简，同时能继续开发 | 用户明确偏好；具体组织方式不在本文件决定 |

性能验收前还需确定：

1. 分辨率和窗口／全屏条件。
2. 目标画质档位。
3. 覆盖地面、天宫外部、室内、飞行、云海和夜景的代表路线。
4. 60 FPS 是平均目标还是持续最低要求，如何记录明显卡顿。
5. 首次启动、进入区域和素材加载时长的可接受范围。
6. 包体、磁盘占用与内存占用上限。

当前不作“全部天气、全部区域、任意视角均恒定 60 帧”的未经验证承诺，也不擅自把 60 帧改成 30 帧。

## 16. 典型用户场景

### UC-01：从江南进入天宫

玩家离线启动作品，在扩大的水乡中控制古装人物行走，观察桥、水道、民居和地面景观；随后起飞、上升并抵达云海中的天宫。玩家能感受到地面和天宫之间的高度关系，以及天宫建筑群的体量。

### UC-02：近距离理解宏大建筑

玩家降落在天宫台阶或平台，使用第一人称仰望宫门与高柱，再切换第三人称观察人物在建筑前的比例。玩家可进入已开放宫殿，并飞上允许落脚的屋顶。

### UC-03：安静观景与留影

玩家在合适的位置坐下，观察光线或时间变化，在夜间欣赏星空、银河和月亮，并保存截图。具体天象和时间功能取决于该交付版本确认的范围。

### UC-04：水中与坠落体验

玩家进入可活动水域，按后续确定的水中规则移动；从高处离开落脚点时，按已确定的飞行与重力规则运动，不应因规则不清而无法继续探索。

### UC-05：未来与朋友同行

3—5 名玩家进入同一场景，能够看到彼此移动，并一起从地面飞向天宫、选择观景位置。聊天、共同天气和其他同步规则不在本场景描述中默认确定。

## 17. 验收条目草案

下表用于后续细化验收，不代表已有实现或测试通过。验收应按各版本批准的功能子集执行。

| 编号 | 验证内容 | 验证方法／预期 | 尚需确定 |
| --- | --- | --- | --- |
| AC-01 | 离线启动 | 断开互联网后，使用已交付文件启动并进入世界 | 启动入口与所需环境 |
| AC-02 | 地面行走 | 可控制人物沿地面、桥和允许通行的台阶移动 | 输入方式和通行区域 |
| AC-03 | 地面尺度 | 按固定步行速度走指定路线约 6—8 分钟 | 路线、速度及计时规则 |
| AC-04 | 地面至天宫 | 操控同一人物从地面飞至天宫并落脚 | 高度、耗时及加载体验 |
| AC-05 | 飞行与重力 | 起飞、飞行、降落与退出飞行后的坠落符合确定规则 | 运动规则 |
| AC-06 | 双视角 | 同一人物位置可切换第一和第三人称并继续移动 | 镜头规则 |
| AC-07 | 宏大感 | 对照参考图，从人物近景、仰视、长阶及飞行远景进行审核 | 审核画面与尺度标准 |
| AC-08 | 视觉相似 | 审核已批准地标的轮廓、材质、光照、云海及空间纵深 | 必交地标与简化边界 |
| AC-09 | 室内与屋顶 | 进入指定宫殿内部，并在指定屋顶降落、站立和离开 | 开放区域清单 |
| AC-10 | 水中活动 | 人物可按确定规则进入水域并活动 | 涉水／游泳／潜水范围 |
| AC-11 | 关门与坐下 | 在指定互动点完成关门和坐下，并可继续探索 | 可交互对象与退出方式 |
| AC-12 | 截图 | 保存当前观景画面为本地图片 | 格式、路径及界面是否隐藏 |
| AC-13 | 时间与天气 | 验证该版本确认的昼夜、天气和切换行为 | 具体种类与变化方式 |
| AC-14 | 夜空 | 夜间显示该版本确认的星空、银河和月亮 | 表现规则及质量标准 |
| AC-15 | 性能 | 在用户目标设备和确定测试条件下评估 60 FPS | 分辨率、画质、指标与路线 |
| AC-16 | 后期联机 | 3—5 人能看到彼此行走、飞行并共同观景 | 仅在联机版验收时执行 |

最终整体体验验收以用户原话为核心：

> 我能操控古装人物，从水乡飞到云海中的巨殿前，切换视角，而且巨殿的尺度和光照接近指定参考图。

## 18. 关键风险与返工来源

| 风险 | 影响 | 在需求阶段需要澄清的事项 |
| --- | --- | --- |
| 图片细节与完整三维世界不等价 | 建筑背面、室内和飞行可见区域需要补充设计 | 地标清单、可达范围、室内深度 |
| 多张图片缺少统一布局 | 可能产生空间关系和风格不一致 | 建筑群关系及审核方式 |
| 超大建筑与步行节奏冲突 | 空间震撼但移动耗时可能过长 | 建筑尺度、速度和关键路线 |
| 60 FPS 与高细节画面存在压力 | 后期可能需要减少细节、效果或范围 | 硬件、画质、分辨率和验收标准 |
| 简易版与完整版边界不明确 | 可能重复制作或对首版产生不同预期 | A、B 版功能与质量差异 |
| 无现成模型且不购买素材 | 特定巨型建筑和雕刻可能需要加工或制作 | 素材可得性、投入时间与可接受简化 |
| 水中、重力、飞行规则未定 | 角色行为、镜头和场景通行可能返工 | 运动规则与异常恢复 |
| 天气与昼夜范围未定 | 环境效果及审核工作量扩大 | 种类、切换和交付阶段 |
| 后期多人状态不明确 | 共同环境和互动规则可能修改 | 同步范围与加入方式 |
| 服务器信息不足 | 无法判断后期资源是否满足需求 | 带宽、配置详情、负载和实测 |
| 缺少明确的画质完成定义 | 易反复修改而无法认定完成 | 固定审核机位及具体差异反馈 |

这些是需要验证和管理的不确定性，不是已经证明无法实现的结论。
